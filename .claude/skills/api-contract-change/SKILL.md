# API 계약 변경

`openapi.yaml`은 별도 저장소인 프론트엔드와의 계약이다. 코드만 바뀌고 명세가 남으면 프론트엔드는 어긋난 사실을 배포 뒤에야 알게 되므로, 코드와 명세를 함께 바꾸고 변경 사항을 알린다.

## 1. 변경 전 확인

- 변경이 [CLAUDE.md](../../../CLAUDE.md)의 오픈 이슈와 관련되면 임의로 정하지 않고 사용자에게 묻는다.
- 아래 절대 규칙에 어긋나지 않는지 본다.
  - `/internal/*` 엔드포인트를 두지 않는다.
  - 카드 필드에는 AI 생성 결과만 담는다. 편집팀 해설은 데모 범위 외다.
  - 원문은 `abstractUrl`, `pdfUrl` 링크만 내려주고 PDF를 프록시하지 않는다.
  - 사용자 데이터와 이용 이벤트를 저장하거나 조회하는 API를 두지 않는다.
  - 응답과 오류에 키, 토큰을 담지 않는다.

## 2. 호환성 판단

| 구분 | 해당 변경 |
| --- | --- |
| 호환 깨짐 | 경로 · 필드 삭제나 이름 변경, 타입 변경, 필수 요청 필드 추가, 응답 필드를 선택으로 변경, 인증 요구 강화, 상태 코드 변경, 커서 형식 변경 |
| 호환 유지 | 새 엔드포인트, 선택 요청 필드 추가, 응답 필드 추가 |

호환이 깨지는 변경이면 구현 전에 사용자에게 알리고 진행 여부를 확인한다. 프론트엔드 배포와 순서를 맞춰야 할 수 있기 때문이다.

## 3. 함께 갱신

- `openapi.yaml`: 없으면 생성해도 되는지 먼저 묻는다.
- `CLAUDE.md`의 API 엔드포인트 표: 경로나 메서드가 바뀔 때
- `CLAUDE.md`의 데이터 모델: 저장 필드가 바뀔 때
- 코드: 역할 분담에 따라 사용자가 요청한 경우에만 Claude가 작성한다

사용자 노출 오류 메시지는 한국어로, 그 외 명세의 식별자는 영어로 쓴다.

## 4. 검증

- `openapi.yaml`을 Swagger Editor에서 검증한다. CLI 검증 도구는 새 의존성이므로 먼저 묻는다.
- 구현이 있으면 FastAPI가 만든 `app.openapi()` 출력과 대조해 어긋난 곳을 찾는다.
- 검증하지 못했으면 검증했다고 말하지 않고, 사용자에게 직접 확인을 요청한다.

## 5. 프론트엔드 공지 초안

Claude가 직접 보내지 않고, 사용자가 전달할 수 있게 아래 형식으로 답변에 적는다. 프론트엔드 개발자가 저장소를 열지 않아도 무엇을 고칠지 알 수 있게 쓴다.

```markdown
### API 변경: <한 줄 요약>

- 구분: 호환 깨짐 | 호환 유지
- 대상: <메서드> <경로>
- 변경 전:
- 변경 후:
- 프론트엔드 조치:
- 적용 시점:
```

## 6. 마무리 보고

바뀐 파일과 검증 결과를 알린다. 그런 다음 커밋 시점임을 알리고, 코드와 명세를 성격별로 나눈 Conventional Commits 메시지를 추천한다. 예: `docs(api): sync openapi.yaml with folder endpoints`
