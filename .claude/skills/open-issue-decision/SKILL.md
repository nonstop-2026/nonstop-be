# 오픈 이슈 결정 반영

오픈 이슈는 사용자가 정하는 항목이다. Claude의 일은 결정을 대신하는 것이 아니라, 정해진 내용이 문서마다 어긋나지 않게 반영하는 것이다.

## 1. 결정 내용 확인

- [CLAUDE.md](../../../CLAUDE.md)의 오픈 이슈에서 해당 번호를 찾는다. 목록에 없는 항목이면 새 결정인지 사용자에게 묻는다.
- 값이나 방식이 분명하지 않으면 묻는다. 추천은 할 수 있지만, 사용자가 확정하기 전에는 반영하지 않는다.
- 무료 한도, 약관처럼 바뀔 수 있는 사실에 기대는 결정이면 공식 문서를 확인한다. 확인하지 못하면 기록에 "미확보"로 적고 사용자에게 알린다.

## 2. 영향 범위 찾기

관련 용어로 `CLAUDE.md`, `docs/spec.md`, `openapi.yaml`, 구현 코드를 모두 검색한다. "미정", "후보" 같은 표현이 남은 곳과, 이 결정에 따라 함께 풀리는 다른 이슈도 확인한다. 예를 들어 배치 실행 환경이 정해지면 `/internal/*` 보호 방식과 `/internal/ingest` 공개 여부도 다시 봐야 한다.

## 3. 문서 반영

| 결정의 종류 | 반영 위치 |
| --- | --- |
| 기술 스택, 인프라 | `CLAUDE.md` 개요 |
| 인증, 데이터 모델, 엔드포인트 | `CLAUDE.md` 해당 절 |
| 기능 동작, 정책 | `docs/spec.md` 해당 절 |
| 변하는 수치 (한도, 상한) | 설정값. 문서에는 설정 이름과 값을 정하는 근거만 적는다 |

- 오픈 이슈에서 항목을 지우되 **다른 번호는 다시 매기지 않는다.** 결정 기록과 대화에서 번호로 참조하기 때문이다.
- 엔드포인트나 요청 · 응답 형식이 바뀌면 `api-contract-change` 스킬을 이어서 따른다.
- 수정이 30줄을 넘으면 먼저 사용자에게 묻는다. `CLAUDE.md`가 200줄을 넘게 되면 세부 내용을 `docs/spec.md`로 옮기자고 제안한다.

## 4. 결정 기록

`docs/decisions.md` 끝에 아래 형식으로 추가한다. 파일이 없으면 생성해도 되는지 먼저 묻는다. 번복할 때는 이전 기록을 고치지 않고 새 기록을 추가해, 왜 바꿨는지 남긴다.

```markdown
## YYYY-MM-DD 이슈 #N: 제목

- 결정:
- 근거:
- 확인한 출처: (URL과 확인 날짜, 또는 미확보)
- 반영 위치:
```

근거는 사용자가 말한 이유를 적는다. 말하지 않았으면 추측해서 채우지 말고 묻는다.

## 5. 마무리 보고

바뀐 파일, 함께 풀린 이슈, 아직 남은 관련 이슈를 알린다. 그런 다음 커밋 시점임을 알리고 Conventional Commits 메시지를 추천한다. 예: `docs: record hosting decision for FastAPI`
